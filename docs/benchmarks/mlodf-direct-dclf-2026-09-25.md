# MLODF runner versus direct post-outage DCLF

Run on September 25, 2026, using Java 21.0.2 on Windows 11 amd64, remote master
`ba589bd2b` plus the local `getMultiOutageMatrixIndex()` runner fix.

All 18 configurations passed: 3,642 surviving-branch comparisons per repetition,
with maximum absolute error **2.68300937023e-11 MW** against a tolerance of
**1e-6 MW**. Each configuration ran three warmups and nine measured repetitions;
every repetition was checked. Outage order reversal also passed.

## Method

- IEEE 14-, 118-, and 300-bus fixtures; simultaneous outages of 2, 3, and 5 lines.
- Deterministic shuffled selection (seed `20260925 + outageCount`) retains only
  outage sets that leave every active bus connected. Candidates are active lines
  not connected to the reference bus. This does not test islanding contingencies.
- Independent networks are loaded and initialized with AC load flow before the
  benchmark. The reference base flows come from a separate standard DCLF solve.
- The actual post-outage network has each selected line set to `status=false`.
  Every direct solve creates a new algorithm, rebuilding and factorizing the
  DCLF matrix. No LODF calculation is used to obtain the reference flows.
- Predictions are `baseFlow + sum(LODF * baseOutageFlow)` in MW, calculated from
  `DefaultDcSensitivityRunner.run()` result rows. Every remaining active branch
  is compared. Opened branches are excluded from the monitor set.
- Timings exclude file parsing, AC initialization, the external base DCLF solve,
  topology selection, and assertions. Runner timings include preparation, its
  base DCLF calculation, factor calculation, in-memory result handling, and flow
  reconstruction. Direct timings include a fresh DCLF solve and flow extraction.
  Execution order alternates to reduce timing bias.
- These are local workflow timings, not isolated MLODF kernel timings or a
  warmed, shared-factorization contingency batch benchmark. No timing assertion
  is imposed. The full runner was slower than direct DCLF in every configuration.

## Reproduce

From the repository root with dependencies already cached:

```powershell
mvn -o -pl ipss.test.plugin.core -am test -Pextended-tests "-Dtest=MultiOutageLodfDclfBenchmarkTest" "-Dsurefire.failIfNoSpecifiedTests=false"
```

The benchmark is tagged `extended`, keeping repeated timing runs out of default
tests. The run completed with 3 parameterized test invocations, no failures,
errors, or skips.

CSV artifacts are under `ipss.test.plugin.core/target/mlodf-dclf-benchmark/`:

- `ieee{14,118,300}-summary.csv`: errors, medians, and exact ordered outage IDs.
- `ieee{14,118,300}-flows.csv`: base, predicted, and direct MW for every monitored
  branch, recorded from the first measured repetition.
- `ieee{14,118,300}-timings.csv`: all nine measured timing samples.

The target artifacts are regenerated by the command above and are not committed.
